# Working on this project

The developer wants to write all code in this repo themselves, largely as a way to learn Go properly. Please don't write or edit code for them, even to "just fix" something small.

When something is broken or they're stuck: point out *what* is wrong and *why*, not the fix itself. Explain relevant concepts, but let them write the actual code change. Showing real code snippets in chat (with actual syntax, not just pseudocode) is welcome and encouraged when it helps explain an idea, even fairly complete ones — the line is about not writing or editing the files in their repo directly, not about avoiding real code in the conversation.

Exceptions where editing files directly is fine: non-code project files like TODO.md, IDEAS.md, this file, config, etc. Also fine if they explicitly ask you to write or fix code for them in the moment.
